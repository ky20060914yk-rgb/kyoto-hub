# 京大InfoHub デザイン用プロンプト集

AI に画面デザインを頼むときに「AI っぽい」仕上がりを避けるためのプロンプトと進め方。
Claude にも、他の AI ツールにも、そのまま貼って使える形にしてある。

## この資料の根拠と限界

- 根拠は次の 2 種類。**どちらも一次資料ではない。**
  1. Claude のデザイン作成機能に付属する作法の資料（「美意識はユーザーと決める」「実データで作る」「テンプレ的な見た目を避ける」など）。
  2. 検索結果で見えた実務者の解説（ブログ記事・解説動画の要約）。各記事の本文は、この環境のネットワーク制限で開けていない。要約だけを見た。
- YouTube の動画は、この環境からは再生も字幕取得もできない。動画から学ぶ場合は、字幕（文字起こし）か要点のメモを貼ってもらう（下の「動画の取り込み」を参照）。
- 以下の規則は「複数の資料で繰り返し出てくる実務の定石」で、効果を実測したものではない。自分のサービスで見て、合わなければ直す。

## 最初に理解しておくこと

AI が作る画面が似通うのは、学習した大量の画面の「平均」を出すからだと説明されている。だから、形容詞（「モダンで」「おしゃれに」）で頼むと平均に落ちる。対策は 3 つ。

1. **具体的な名前で方向を示す。** 実在のブランド、雑誌の誌面、時代、様式。「モダン」ではなく名前で指定する。
2. **やってほしくないことを、先頭に書く。** 禁止リストは、肯定の文章を何行書くよりも効く、とされる。
3. **工程を分ける。** レイアウト、文字・余白、色、動きを、一度に直さない。

## 1. プロジェクトの前提ブロック（毎回、冒頭に貼る）

```
【サービス】京大InfoHub（京都大学の学生専用。授業レビュー、過去問・資料、教科書の譲り合い）
【利用者】京大生。スマホで、履修を決める前や試験前に、短時間で開く。
【画面の主な仕事】履修を決める材料（先輩の声、楽単度、過去問の有無）を、速く見つける。
【構成】下タブ4つ（さがす／時間割／教科書／マイページ）。ログインには @st.kyoto-u.ac.jp が必要。
【今の見た目】紺（#0F4C81）を基調にした Material 3、スレート系のグレー、Inter。これを置き換えたい。
【守ること】アプリはお金を扱わない。教科書・参考書のみ。クレジットは購入できない。
【中身】ダミーを作らない。次の実データを使う: tools/courses.json の科目名・教員名、レビューの項目（楽単度、出席、試験の傾向）。
        実データがない箇所は、[ここに実データ] と明示する。数字や統計を作らない。
```

## 2. 禁止リスト（毎回、前提ブロックの次に貼る）

```
次は使わない。
- 紫から青へのグラデーション、グラデーションの背景
- Inter、Roboto、Arial、Space Grotesk
- 絵文字を、見出しや飾りの記号として使うこと
- すべての要素を同じ角丸・同じ影のカードに入れること
- 左端に色の帯を付けたカード
- 番号付き（01/02/03）の飾り。内容が本当に順序を持つ場合だけ許可
- 中央揃えだけの構成
- 生成り色の背景＋セリフ体の見出し＋赤茶の差し色（よくある AI の定番）
- 「サンプル」「ダミー」「Lorem ipsum」「Welcome to…」
- 意味のない数字、統計、アイコン
```

## 3. 方向を決めるプロンプト（色や形の前に）

```
前提ブロックを読んだうえで、画面の「方向」を 3 案出して。条件:
- 3 案は「色違い」ではなく、画面の主役が違うこと（例: 時間割が主役／先輩の声が主役／
  科目ごとの掲示板が主役）。
- 各案に、(a) 参考にした実在のデザイン（ブランド、雑誌、様式。名前で）、(b) その案が優れる点、
  (c) 弱点を書く。1 案だけ推す書き方をしない。
- まだ色もフォントも決めない。線画（ワイヤーフレーム）で構造だけ見せる。
- 参考のデザインを、そのまま写さない。何を取り入れるかを書く。
```

## 4. 工程別の仕上げプロンプト

### 4-1. グレースケールで構造（色を入れない）

```
決まった方向の「さがす」画面を、色なし（白・黒・グレーだけ）で作って。
- 情報の重要度を、サイズ、太さ、濃さの差で示す。色で示さない。
- 余白は 4, 8, 12, 16, 24, 32, 48, 64 の中だけで決める。迷ったら広めにして、あとで詰める。
- 太さは 2 種類まで。サイズの段階は 5 段階まで。
- 全部のタップ対象は 44px 以上。
```

### 4-2. 文字と余白だけを直す

```
色と構造は変えず、文字だけ直して。
- 日本語の見出しと本文の組み合わせを理由つきで選ぶ（Google Fonts）。Inter は使わない。
- 行の長さは 1 行 30〜40 文字。行間は本文で 1.7 前後。
- 数字は等幅（tabular-nums）。単位や注釈は小さく、薄く。
- 見出しは text-wrap: balance。
```

### 4-3. 色を入れる

```
グレースケールの画面に色を入れて。
- 色は「地、文字、主役の色、補助の色」の 4〜6 個を、名前付きで先に定義する。
- 主役の色は 1 つ。使う場所を決め、全体の 5% 以下に抑える。
- グレーには、主役の色の方向へ少し色味を寄せる。
- 文字のコントラストは、本文 4.5:1 以上、24px 以上の大きな文字で 3:1 以上。
- 色だけで意味を分けない。明るさの差も付ける。
- ダークモードは、単なる反転にしない。
```

### 4-4. 動き（最後に、少しだけ）

```
動きを付けて。ただし 1 か所だけ。
- 「画面を開いた瞬間」の演出を 1 つ。それ以外のホバー等は最小限。
- prefers-reduced-motion のときは止める。
- 初回の表示を重くしない（アニメーション用のライブラリを足さない）。
```

## 5. 自己レビューのプロンプト（出す前に、毎回）

```
作った画面を、次の観点で厳しく自己採点して。直せるものは直してから見せて。
1. 前提ブロックの実データだけを使っているか。ダミーが残っていないか。
2. 禁止リストに触れていないか（1 つずつ確認）。
3. この画面の「主役」は何か。1 つに絞れているか。
4. 他のサービスに差し替えても成り立つ画面になっていないか。このサービスにしかない要素は何か。
5. 同じ形の要素が並びすぎていないか。強弱があるか。
6. スマホ幅（390px）で、文字が切れたり、小さすぎたりしないか。
7. キーボードと読み上げで操作できる部品（button, a, input + label）になっているか。
最後に、直していない問題を正直に列挙して。
```

## 6. 参考デザインを言葉にするプロンプト

```
次のアプリ／サイトを、デザインの観点で分析して（私が好きな見本。そのまま写さない）。
[名前または URL]
- 余白の取り方、文字の大小と太さ、色の数と使い所、角丸と影の使い方、情報の密度。
- 「なぜプロっぽく見えるのか」を、上の項目ごとに 1 行で。
- 京大InfoHub に取り入れるなら、どの要素を、どう変えて使うか。
- 取り入れてはいけない（そのまま写すことになる）要素。
```

## 7. 動画の取り込み（YouTube などを使うとき）

AI は YouTube を再生できない。字幕を貼る。

```
次は、デザインの解説動画の字幕（または自分のメモ）。
[ここに貼る]
やって。
1. 主張を 10 個以内の短い規則にまとめる。動画が言っていないことを足さない。
2. 各規則に、動画内の根拠（発言の引用か、時刻）を付ける。
3. 根拠が弱い規則、主観が強い規則に印を付ける。
4. 既にこの資料（design-prompts.md）にある規則と重なるものと、新しいものを分ける。
5. 新しい規則を、この資料の形式（禁止リスト、工程別プロンプト、自己レビュー）に、どこへ追加するか提案する。
```
